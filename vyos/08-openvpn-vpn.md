# 08 — OpenVPN remote-access VPN, FreeIPA password auth (N7)

Remote-admin VPN on VyOS 1.4.4, **natively** (no extra VM). OpenVPN in server mode on `vtun0`,
its own tunnel subnet + firewall zone. **Authentication is live against FreeIPA** via the
bundled `openvpn-auth-ldap.so` plugin — users log in with their IPA username + password; no
per-user keys or certs to issue or revoke. Disable/offboard in IPA → next connect fails.
Cite: **N7.1**, **N7.2**, **N7.3**, **N7.4**, **N7.5**, **N7.6**.

| Thing | Value |
|---|---|
| Interface | `vtun0` (OpenVPN server mode) |
| Transport | `udp/1194` on WAN (`88.200.24.237`) |
| Tunnel subnet | `10.7.99.0/24` + `fd07:99::/64` |
| Tunnel type | **split tunnel** — only LAN/DMZ routes pushed; no internet egress via VPN |
| Server (channel) PKI | **VyOS-generated CA + server cert** (secures the TLS control channel; clients trust it via the bundled CA) |
| User auth | **FreeIPA LDAP**, username+password, no client cert (`--verify-client-cert none`) |
| Authorization | live `vpn-users` membership, enforced in the LDAP `SearchFilter` |

> **Two separate trust pieces, don't conflate them.** (1) The OpenVPN *control channel* is
> secured by a server cert — generated by VyOS's own PKI, since there's no certmonger on VyOS.
> Clients only need to *trust* it (we ship the CA in the `.ovpn`). (2) *User identity* comes
> from FreeIPA over LDAPS. The user's real IPA password is what authenticates — so the LDAP
> bind **must** be over TLS.

## ⚠️ Lockout safety
You're still managed over the **TEMP `WAN-LOCAL` rule 40 (tcp/22)**. This runbook removes it in
§7 — **only after** you've proven login *through the tunnel*. Keep it until then.

> **Prerequisite — the router must resolve `kyber.local`.** `openvpn-auth-ldap` resolves
> `kyber-ldap.kyber.local` using the router's *own* resolver, not the DNS forwarder. Apply the
> **"Router self-resolution"** step in `vyos/03-ntp-dns-hostname-setup.md` first (`system
> name-server 127.0.0.1` + the loopback forwarder listen/allow-from), or the LDAP bind fails
> with *"Unable to enable STARTTLS: Can't contact LDAP server"*.

## 3. Generate the OpenVPN channel PKI (on `kyber-rtr`)

No certmonger on VyOS, so generate a small self-contained CA + server cert for the control
channel. Follow the prompts (accept defaults; CN can be `kyber-vpn`):

```sh
generate pki ca install ca-vpn
generate pki certificate sign ca-vpn install srv-vpn
```
These write `set pki ca ca-vpn …` and `set pki certificate srv-vpn …` into the config. Keep the
CA certificate text handy (`show pki ca ca-vpn`) — it goes into every client `.ovpn` (§8).

## 4. Configure the OpenVPN server + LDAP auth

```sh
configure
set interfaces openvpn vtun0 mode 'server'
set interfaces openvpn vtun0 protocol 'udp'
set interfaces openvpn vtun0 local-port '1194'
set interfaces openvpn vtun0 device-type 'tun'
set interfaces openvpn vtun0 persistent-tunnel

# tunnel addressing (dual-stack inside the tunnel)
set interfaces openvpn vtun0 server subnet '10.7.99.0/24'
set interfaces openvpn vtun0 server subnet 'fd07:99::/64'

# split tunnel: push only the company routes (NOT redirect-gateway)
set interfaces openvpn vtun0 server push-route '10.7.0.0/24'
set interfaces openvpn vtun0 server push-route '192.168.7.0/24'
set interfaces openvpn vtun0 server push-route '2001:1470:fffd:9a::/64'
set interfaces openvpn vtun0 server push-route '2001:1470:fffd:99::/64'
# push the router as DNS so kyber.local resolves to INTERNAL addresses (N7.6)
set interfaces openvpn vtun0 server name-server '10.7.99.1'

# control-channel PKI (from §3) + modern crypto
set interfaces openvpn vtun0 tls ca-certificate 'ca-vpn'
set interfaces openvpn vtun0 tls certificate 'srv-vpn'
set interfaces openvpn vtun0 encryption cipher 'aes256gcm'
set interfaces openvpn vtun0 hash 'sha256'

# keepalive — REQUIRED on UDP. Pings every 10s, declares dead + restarts after 60s
# (interval × failure-count). Without it an idle tunnel silently dies: the NAT/conntrack
# pinhole for the udp/1194 flow expires, server→client replies get dropped, and the client
# sits there showing "connected" (persist-tun) while DNS times out and SSH hangs. The server
# auto-pushes this to clients, so nothing needs adding to the .ovpn.
set interfaces openvpn vtun0 keep-alive interval 10
set interfaces openvpn vtun0 keep-alive failure-count 6

# --- the load-bearing bit: FreeIPA password auth, no client certs (verbatim from VyOS docs) ---
set interfaces openvpn vtun0 openvpn-option "--plugin /usr/lib/openvpn/openvpn-auth-ldap.so /config/auth/ldap-auth.config"
set interfaces openvpn vtun0 openvpn-option "--verify-client-cert none"
set interfaces openvpn vtun0 openvpn-option "--username-as-common-name"
```

> Dropped from the docs' sample on purpose: `--comp-lzo` (compression = VORACLE risk) and
> `--push redirect-gateway` (that's a *full* tunnel; we push split routes instead).

## 8. Client config (N7.5)

There is **nothing to provision per user** — every `vpn-users` member uses the same `.ovpn`
and authenticates with their own IPA credentials. Build it from
[`/services/vpn/kyber.ovpn.example`](../services/vpn/kyber.ovpn.example).

Get the CA certificate in PEM — this is an **operational-mode** command (run it from the
`vyos@kyber-rtr:~$` prompt; from configure mode prefix it with `run`):

```sh
show pki ca ca-vpn pem          # configure mode:  run show pki ca ca-vpn pem
```

Copy **only** the `-----BEGIN CERTIFICATE----- … -----END CERTIFICATE-----` block into the
`<ca>…</ca>` tags of the client config. Leave the private-key section on the router — it must
never go in a client file. No `<cert>`/`<key>` either (password auth, `--verify-client-cert none`).

Distribute that one file; users run `openvpn --config kyber.ovpn` (or import it) and are
prompted for their IPA username + password.

## 10. Follow-ups
- **Offboarding = one action:** `ipa user-disable <u>` or remove from `vpn-users`. No router/cert/peer cleanup — auth is live.
- **Optional MFA:** VyOS OpenVPN supports native TOTP (`server mfa totp`) if you later want a second factor on top of the IPA password.
- Sample client config lives in [`/services/vpn/`](../services/vpn/) (N7.5); the bind-config template is `ldap-auth.config.example` (the real one with the password stays on the box, uncommitted).
